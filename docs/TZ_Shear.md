# ТЗ: shear (наклон линий спектра, ось Y базиса)

Вторая часть калибровки. Shear — угол между вектором полосы и линиями внутри неё,
то есть наклон щели к дифракционной решётке. Вместе с углом полосы даёт **базис
системы координат спектра**: X вдоль оси длин волн, Y вдоль спектральных линий.

Реализация: `spectre/calib.py`, `ShearParams` / `ShearResult` / `find_shear` +
общий класс `BandStrip`.

## Постановка, дословно от Игоря

> Точно также как мы перебирали наклоны, перебираем значения shear (наклона оси Y
> к оси X внутри полосы). Для каждого из них строим одномерную проекцию суммы
> изображения, только теперь по оси Y. Суммироваться будут теперь пиксели по
> ширине полосы (края где нехватка данных выбрасываем из анализа). Из полученных
> проекций выбираем sharpest one, где sharpness определяется как
> среднеквадратичное отклонение между gaussian_blur(1), и gaussian_blur(4).

И постановка задачи целиком:

> Задача всей калибровки это получить базис системы координат спектра, где X
> вдоль оси длинн волн, а Y вдоль спектральных линий. Они не перпендикулярны
> между собой из-за не идеального поворота щели и решетки, и не перпендикулярны
> сторонам кадра из-за неидеального накручивания камеры на спектрограф.
>
> НАША ЗАДАЧА БАЗИС СИСТЕМЫ КООРДИНАТ - ЭТО ДВА ВЕКТОРА

## Решения по деталям (ответы Игоря на вопросы)

1. **Края отбрасываются**, и это именно то, что имелось в виду: «Всё равно там
   нет данных с запасом (дальний УФ и дальний ИК за пределами чувствительности
   камеры)». В коде отбрасывается один и тот же интервал для всех углов,
   посчитанный по максимальному углу диапазона, чтобы кривая была сравнима.
2. **Нормировка на число сложенных пикселей** (среднее арифметическое, а не
   сумма) — принято.
3. **Один параметр в UI — множитель**, соотношение 1:4 зашито: «Давай сделаем
   один параметр - множитель, и вынесем только его. А соотношение 1:4 оставим. У
   нас уже слишком перегружен параметрами UI».
4. **Диапазон ±10°, шаг 0.05°.**
5. **Показывать кривую** наклон–чёткость от −10 до +10: «По кривой видно шум там
   или сигнал».
6. **Никаких целочисленных операций, всё во float. Субпиксельная интерполяция не
   нужна, всё усреднится.** Реализовано так: координата каждого пикселя вдоль
   оси длин волн считается в плавающей точке, пиксель попадает в ближайший бин
   одномерного профиля; никаких предварительных целочисленных сдвигов картинки и
   никакой интерполяции. Обоснование Игоря: «я не парюсь с целочисленными
   сдвигами потому что всё усреднится на тысячах пикселей. Нам важен
   качественный относительный результат, а не количественные значения потока».
7. **Источник с линиями** обеспечивает Игорь: по чистому континууму заострять
   нечего.

## Что зафиксировано в коде

* берётся лента пикселей между границами полосы (`BandStrip`), у каждого пикселя
  известно точное дробное расстояние от осевой линии полосы;
* для пробного угла ψ (от оси Y кадра) координата вдоль спектра
  `u = x - v * k`, где `k = tan(psi) / (1 - tan(theta) * tan(psi))`, theta —
  угол полосы; k и есть `du/dv`;
* профиль = сумма по бинам u, делённая на число попавших пикселей;
* резкость = RMS разности `blur(1*scale) - blur(4*scale)`, максимум по ψ;
* результат: наклон линий от оси Y, shear как отклонение от перпендикулярности
  (`theta + psi`), `du/dv`, и сам базис — два единичных вектора в координатах
  кадра;
* инвариант для проверки: shear не должен меняться при повороте камеры, потому
  что угол полосы и наклон линий уезжают на равные величины в противоположные
  стороны.

Оверлей: девять пунктирных полупрозрачных зелёных линий поперёк полосы по
найденному направлению, равномерно вдоль измеренного участка, с выходом на 15 %
за края полосы. Пунктир задан в экранных пикселях, чтобы не менялся при зуме и не
закрывал спектр. Показываются только после `Find shear`.

## Ограничение точности

Плечо здесь — ширина полосы (десятки–сотня пикселей), а не её длина, поэтому
пиксельный смаз соответствует большому углу: при ширине 125 px один пиксель это
`atan(1/125) ~ 0.45°`. Шаг мельче 0.05° смысла не имеет.
